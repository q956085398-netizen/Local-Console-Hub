# 产品与行为规范

本文档定义 Local Console Hub 的核心产品行为。具体 UI 与技术实现可以变化，但除非经过明确讨论，本文中的行为原则不应被随意破坏。

## 1. 核心对象：Managed Session

Hub 中的基本管理单位不是“窗口”，而是 **受管会话（Managed Session）**。

每个会话至少应具有：

- 唯一 ID；
- 用户可读名称；
- 类型；
- 工作目录；
- 启动命令或 shell；
- 当前状态；
- PID / 进程树信息；
- 用途说明；
- 关闭影响说明；
- 日志策略；
- 可选 URL / 端口；
- 可选依赖关系。

会话是用户理解系统的主要入口，PID 只是实现细节。

## 2. 会话类型

### 2.1 Service Session

适用于：

- SillyTavern；
- ComfyUI；
- KoboldCpp；
- 各类 WebUI；
- 长期运行的本地 API；
- 其它“启动后长期挂着”的本地程序。

Service Session 的重点是：

- 生命周期；
- 健康状态；
- 端口 / URL；
- 日志；
- 资源占用；
- 依赖；
- 安全停止。

它可以有终端，但终端不是唯一入口。

### 2.2 Interactive Terminal Session

适用于：

- PowerShell / CMD / pwsh；
- Python / Node REPL；
- 需要键盘输入的测试工具；
- 交互式 CLI；
- 临时调试环境。

Interactive Terminal Session 必须是真正的 PTY/ConPTY 会话，而不是只读 stdout 面板。

最少需要支持：

- stdin；
- stdout/stderr；
- 键盘输入；
- Ctrl+C 等常用控制操作；
- resize；
- Unicode；
- 光标与基础 ANSI 控制序列。

如果某个会话“可以看输出但不能输入”，它只能被称为日志视图，不能被标记为 Interactive Terminal。

## 3. 状态模型

初期基础状态：

- `Stopped`
- `Starting`
- `Running`
- `Stopping`
- `Exited`
- `Error`

后续可扩展：

- `Ready`
- `Busy`
- `Degraded`
- `Unhealthy`

状态来源可以是：

1. 进程是否存在；
2. 端口是否监听；
3. HTTP 健康检查；
4. 应用适配器；
5. 用户配置的检查命令。

UI 必须区分“进程活着”和“服务可用”，不能把两者混成同一个概念。

## 4. 生命周期行为

### 启动

启动时 Hub 应：

1. 解析配置；
2. 确认工作目录；
3. 创建受管进程；
4. 保存 PID 与子进程关系；
5. 创建或连接终端；
6. 根据日志策略决定是否持久化输出；
7. 更新状态。

### 停止

默认停止顺序：

1. 尝试优雅停止；
2. 等待可配置超时；
3. 如仍未退出，提示或执行进程树终止策略。

“停止”和“强制结束”必须在 UI 与实现上区分。

### 重启

重启应等价于一次完整的停止 + 启动，不应在旧进程未退出时盲目再拉起一份。

## 5. 交互终端规范

这是核心能力之一。

### 必须

- 用户可以输入；
- 能运行交互式 CLI；
- 终端尺寸变化能传递给 PTY；
- 切换会话不会销毁终端；
- Hub 隐藏到托盘时会话继续运行；
- 恢复窗口后能继续查看和输入。

### 默认不做

- 默认记录用户输入；
- 默认把每个 shell 会话写入磁盘日志；
- 全局接管系统所有终端；
- 捕获 AI Agent 自己创建的后台控制台。

## 6. “新终端进入 Hub”的定义

初期定义为：

> 所有由 Hub 主动创建、或明确通过 Hub 启动的终端，进入 Hub 内部会话列表。

不是：

> 系统上任何新出现的 cmd / PowerShell 都必须被强行抓进 Hub。

推荐入口包括：

- “新建 PowerShell”
- “新建 CMD”
- “新建 pwsh”
- “从当前目录打开受管终端”
- `hub shell`
- `hub run <session>`

后续若增加系统级接管能力，应是显式可选，并默认关闭。

## 7. UI 信息层级

### 左侧会话列表

应快速回答：

- 是什么；
- 是否在运行；
- 是服务还是交互终端；
- 端口 / 简短用途；
- 是否 Busy / Error。

### 主区域

优先提供：

- 名称；
- 状态；
- PID；
- 用途；
- 关闭影响；
- URL / 端口；
- 工作目录；
- 操作按钮；
- 终端 / 日志切换。

### 主要操作

Service Session：

- 启动；
- 停止；
- 重启；
- 打开网页；
- 查看终端；
- 查看日志；
- 打开目录。

Interactive Terminal：

- 聚焦终端；
- 重启会话；
- 停止；
- 打开工作目录；
- 可选“从当前会话创建新终端”。

## 8. 托盘行为

默认：

- 点击窗口右上角关闭按钮：隐藏到系统托盘；
- 受管进程继续运行；
- 托盘菜单提供“显示主窗口”；
- 真正退出必须有明确入口。

真正退出时，如果仍有受管进程运行，必须提示用户选择：

- 退出 Hub，但保留可分离的后台进程（若实现支持）；
- 停止全部受管进程后退出；
- 取消。

不得悄悄杀掉所有服务。

## 9. 日志与终端缓冲区

三者必须严格区分：

### 9.1 Terminal Buffer

用于 UI 回看近期终端内容。

特点：

- 内存中；
- 有大小上限；
- 默认不会产生文件；
- 会话销毁后可丢失。

### 9.2 Hub Captured Log

由 Hub 根据策略保存的 stdout/stderr。

特点：

- 可持久化；
- 有元数据；
- 有轮转；
- 用户能看到路径；
- 不默认记录 stdin。

### 9.3 External / Application Log

应用自己生成的日志。

Hub 可以：

- 关联；
- 索引；
- 打开；
- 搜索（后续）。

Hub 不应在没有必要时再复制一份相同内容。

详细规则见 `LOGGING.md`。

## 10. 配置规范原则

配置必须：

- 可人工阅读；
- 可人工编辑；
- 错误信息明确；
- 支持注释或有等效文档机制；
- 允许单会话覆盖全局默认值；
- 对危险行为使用显式配置。

配置不应要求用户理解内部 PID 或 UI 实现细节。

## 11. 非功能目标

### 性能

- 空闲状态避免高频轮询；
- 终端不可见时不需要持续重绘；
- 日志读取应增量进行；
- 资源监控应低频或按需；
- 托盘常驻时保持低 CPU 占用。

### 稳定性

- Hub UI 崩溃不应无条件杀掉服务；
- 进程结束后状态必须可靠更新；
- 重启不能产生重复实例；
- 路径、命令、编码错误需要明确反馈。

### 隐私

- 默认不持久化交互 shell 内容；
- 默认不记录 stdin；
- 日志目录位置必须透明；
- 未来若支持命令历史，必须显式开启。

## 12. MVP 验收关键场景

MVP 至少要通过：

1. 同时启动 SillyTavern、ComfyUI 和一个 PowerShell；
2. 三者只占一个 Hub 主窗口；
3. PowerShell 可以真正输入命令并看到输出；
4. 切换到 ComfyUI 能看到实时输出；
5. 点 X 后 Hub 进入托盘，三个会话继续运行；
6. 恢复窗口后终端仍可继续交互；
7. 普通 PowerShell 默认没有生成磁盘日志；
8. 为 ComfyUI 开启日志后，可以明确找到本次运行对应文件；
9. 停止某个会话不会误杀其它会话；
10. AI Agent 自己创建的后台进程不会自动出现在 Hub 中。
