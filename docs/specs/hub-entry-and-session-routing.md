## 用户已明确的需求

1. 启动 Hub 不应要求另一个终端窗口长期占用任务栏。
2. “新建 PowerShell / 服务”入口必须有实际功能。
3. 对已经运行的应用再次点击，应唤出已有实例，避免再次启动一份。
4. 日常 PowerShell 启动入口应能够唤起 Hub，并在里面新建终端。
5. 对已有内置控制台的应用，例如秋叶 ComfyUI 启动器，不必重复收入 Hub 内部终端。
6. 保留下方深色 Hub 标题栏，消除顶部重复标题；应用图标采用下方标题栏中的 Hub 图标。合并标题栏时仍需保留常规窗口操作能力。

## 与既有规范的关系

- `docs/PRODUCT_SPEC.md` §6 和 `docs/DECISIONS.md` D-002 默认只归集由 Hub 创建或明确通过 Hub 启动的终端，不全局接管系统终端。第一轮已确认通过改造日常快捷方式进入 Hub，继续保留此边界。
- `docs/ROADMAP.md` Phase 4 将快速新建受管 shell 列为后续候选功能，而用户现已要求实际可用。
- `docs/DECISIONS.md` D-013 记录的应用图标与用户本次选择不同。本次明确选择应在后续实现时反映到图标来源及相关规范。

## 当前核实事实

- `src-tauri/src/main.rs` 只在 release 构建使用 Windows GUI 子系统；开发构建不能据此认定不会出现控制台窗口。
- `src-tauri/tauri.conf.json` 保留系统标题栏，`src/components/title-bar/TitleBar.tsx` 同时渲染内部标题，产生用户截图中的重复层级。
- `TitleBar.tsx` 的 `HubMark` 是下方图标的现有矢量来源。
- `src/components/sidebar/Sidebar.tsx` 的两个新建按钮都调用 `onAdd`，`src/app/App.tsx` 将其转为 `new-session` 动作。后端现有 IPC 表没有创建会话命令；快速创建并未形成完整功能链。
- `src-tauri/src/lib.rs` 的启动流程和 `Cargo.toml` 未见 Hub 单实例协调机制。当前源码不能保证再次启动只唤出已有 Hub。
- `SessionCore::start` 会拒绝同一会话在运行中再次启动；这与跨 Hub 实例复用、唤起第三方应用窗口是不同问题。
- 现有会话类型只有 `service` 和 `terminal`；关联外部日志不等于支持“应用自带控制台、不收入 Hub 终端”的启动模式。
- 未在当前入口实现中找到将外部 PowerShell 快捷方式请求转发给 Hub 的处理链。原有快捷方式的实际目标尚未读取，不据截图认定其已配置为 Hub 入口。

## 第一轮已确认（用户回复：都同意推荐选项）

- Q1：重复启动规则覆盖 Hub 本身和配置的应用。再次启动 Hub 恢复已有窗口；对已运行应用选中已有会话，有独立窗口时唤出该窗口。
- Q2：将用户日常使用的 PowerShell 快捷方式改为 Hub 启动入口。每次点击在同一个 Hub 内新建终端；系统及其它软件自行启动的 PowerShell 保持原行为。见 `docs/adr/0001-explicit-hub-entry.md`。
- Q3：自带控制台的应用继续保留 Hub 启动入口，不重复展示内嵌终端。添加时推荐合适模式并允许手动修改，不仅凭“ComfyUI”名称决定。
- Q4：快速新建 PowerShell 立即创建临时终端，默认不记录日志；需要复用时再保存。配置应用使用后续 Q11 确认的“添加应用”次要入口，填写配置后保存。

## 第二轮确认及补充（用户回复：接受推荐项，原以为新建服务只是新打开 PowerShell）

- Q5：Hub 外已经运行的应用，能可靠识别时直接唤起；无法确定时提示关联已有实例或明确新开，不直接重复启动。关联需要可靠身份依据；不以同名进程或端口占用单独认定为同一个应用。
- Q6：独立窗口应用默认独立运行，不参与停止全部，真正退出 Hub 后继续运行。需要 Hub 管理启停的应用单独启用该选项。见 `docs/adr/0003-independent-application-lifecycle.md`。
- Q7：新终端优先 PowerShell 7，未安装时使用 Windows PowerShell。应用内快速新建默认用户主目录，快捷方式或目录入口使用其指定目录。
- Q8：临时终端结束后保留列表项和本次内存输出，允许手动移除；真正退出 Hub 后不恢复未保存的临时终端。保存配置仅保存启动方式，不恢复此前执行的命令。
- Q9：添加应用表单包含名称、工作目录、启动命令、Hub 内显示或独立窗口模式，以及可选用途、关闭影响、端口、网页地址、日志策略。用户说明其对“新建服务”的理解是新打开 PowerShell；Q11 因此将该表单放到独立次要入口，不作为快速新建的默认交互。
- Q10：关闭终端会话结束其所属进程树，并明确提示影响；持续运行的程序可保存为服务会话。关闭 Hub 主窗口仍只隐藏到托盘，会话继续运行。这是后续实现与原生验收目标，不能据现有 PTY 的 shell 终止行为认定已经满足。

## 第三轮已确认（用户回复：同意）

- Q11：快速主入口命名为“新建 PowerShell”，点击立即创建临时终端；将可复用应用的配置表单放到独立的次要入口“添加应用”。原“新建 PowerShell / 服务”混合文案取消。

## 最终行为范围

- Hub 启动：面向日常使用提供直接启动的应用入口，不需要常驻启动终端；重复启动、最小化或托盘隐藏后的启动请求均交给已有 Hub。
- 请求区分：“打开 Hub”恢复现有窗口；“新建 PowerShell”恢复窗口并新增一个临时终端；“打开已配置应用”复用已有运行实例或启动尚未运行的应用。显式新建终端允许多会话，不应被应用去重规则吞掉。
- 终端入口：主入口直接新建；保存启动配置作为后续可选操作。默认 PowerShell 版本和目录遵守 Q7；不自动记录输入或持久化普通 shell 输出。
- 应用入口：“添加应用”填写并保存配置；支持 Hub 内显示与独立窗口模式。对自带控制台的应用推荐独立窗口模式，允许手动更改；不能仅凭应用名称自动判定。
- 实例复用：先确认已有实例；可靠识别时唤起，不确定时交由用户选择关联或明确新开。关联已有进程本身不应被当成获得终止其进程树的授权。
- 生命周期：关闭主窗口隐藏到托盘；关闭某个终端结束其所属进程树并说明影响。独立窗口应用默认不随停止全部或退出 Hub 结束，需要启停管理时单独启用。
- 临时性：结束的临时终端保留本次列表项和内存输出，允许移除；真正退出后不恢复未保存项。已保存配置保留启动方式，不保留命令执行现场。
- 视觉身份：保留用户选择的下方深色标题及 Hub 图标，将常规窗口操作合并到该标题栏；图标用于应用各 Windows 展示入口。

## 实现顺序

1. 诊断实际启动入口及额外终端的来源，修正常规启动路径；建立单个 Hub 接收并区分启动请求的机制。
2. 完成临时终端创建、动态列表更新、版本和目录选择，以及终止终端所属进程树的能力。
3. 完成保存终端配置和添加应用，保持已有用户配置内容；配置保存失败时反馈实际错误，不显示成功。
4. 实现应用实例复用、独立窗口唤起、展示模式及生命周期选项。
5. 将日常 PowerShell 快捷方式接入 Hub 请求，保留系统和其它软件原有终端行为。
6. 合并标题栏和图标，完成原生 Windows 验收。
