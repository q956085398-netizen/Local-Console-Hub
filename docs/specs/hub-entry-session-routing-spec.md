# 让 Hub 成为实际启动中心：单实例入口、快速 PowerShell 与应用归集

日期：2026-09-30。状态：产品行为及测试边界已由用户确认；实现和本规格的原生验收尚未执行。

## Problem Statement

用户希望用 Local Console Hub 减少任务栏上散落的终端，但目前日常入口与 Hub 内部会话没有形成完整使用链：启动 Hub 仍可能依赖一个常驻终端；“新建 PowerShell / 服务”只是未接入的按钮；再次点击应用可能另开实例；原有 PowerShell 入口仍打开独立终端。对于秋叶 ComfyUI 启动器这类自带控制台的应用，强行重复内嵌没有必要。系统标题栏和内部标题栏重复，应用图标也与用户选择的内部 Hub 图标不同。

用户将“新建服务”理解为新打开一个 PowerShell。这说明现有入口文案混淆了“临时交互终端”和“保存应用启动配置”，不能通过给快速新建按钮增加表单来解决。

当前代码已有真实 ConPTY 终端、Session Core 生命周期、服务进程树监管、托盘与日志策略，但没有完整的动态会话创建接口、Hub 单实例请求转发、外部 PowerShell 快捷方式路由或独立窗口应用模式。Release 已采用 Windows GUI 子系统，实际多余启动终端的来源仍需在实现阶段诊断，不能仅凭截图归因于打包配置。

## Solution

让一个 Hub 接收明确的启动意图：普通打开恢复已有 Hub；“新建 PowerShell”在同一个 Hub 内立即新增临时终端；打开已配置应用则启动或唤起已有实例。用户日常使用的 PowerShell 快捷方式改为 Hub 启动入口，系统和其它软件创建的 PowerShell 保持原行为。

主入口命名为“新建 PowerShell”，不要求填写表单。次要入口命名为“添加应用”，用于保存名称、目录和启动方式。自带控制台的应用推荐使用独立窗口模式，仍可从 Hub 启动和唤起；默认不参与停止全部或随 Hub 退出。

只保留用户选定的深色内部标题栏，将窗口操作融入其中，统一应用、任务栏、托盘及快捷方式图标为该标题栏的 Hub 图标。

## User Stories

1. As a Windows 用户, I want 直接打开 Hub 而不需要常驻启动终端, so that 任务栏上不会因为使用 Hub 又多出一个终端。
2. As a Windows 用户, I want 再次点击 Hub 入口恢复已有窗口, so that 不会重复打开 Hub。
3. As a 托盘用户, I want 点击 Hub 入口恢复隐藏的 Hub, so that 不必寻找托盘图标才能继续操作。
4. As a Windows 用户, I want 最小化后的 Hub 能被再次点击恢复, so that 日常启动入口可以兼作返回入口。
5. As a Windows 用户, I want 冷启动期间连续请求也交给同一个 Hub, so that 不会出现两个 Hub 分别启动应用。
6. As a 交互终端用户, I want 点击“新建 PowerShell”立即打开内部终端, so that 日常命令无需先填写配置。
7. As a 首次安装用户, I want 没有任何已配置会话时也能新建 PowerShell, so that 空工作区不会阻止开始使用。
8. As a 交互终端用户, I want 新建后自动选中并聚焦终端, so that 可以立即输入命令。
9. As a 交互终端用户, I want 每次主动新建产生一个独立终端, so that 可以同时开展多个任务。
10. As a Windows 用户, I want 日常 PowerShell 快捷方式打开 Hub 内的新终端, so that 不再散落独立终端窗口。
11. As a Windows 用户, I want Hub 尚未运行时快捷方式也能创建终端, so that 不必先手动打开 Hub。
12. As a Windows 用户, I want Hub 已在托盘时快捷方式恢复窗口并新建终端, so that 入口行为保持一致。
13. As a PowerShell 用户, I want 默认优先使用已安装的 PowerShell 7, so that 与日常使用的 shell 一致。
14. As a PowerShell 用户, I want 没有 PowerShell 7 时使用 Windows PowerShell, so that 无需额外安装即可开始使用。
15. As a 交互终端用户, I want 应用内新终端默认进入用户主目录, so that 不会意外从系统目录开始工作。
16. As a 目录入口用户, I want 新终端使用入口指定的工作目录, so that 不必每次重新切换目录。
17. As a 交互终端用户, I want shell 或目录不可用时看到具体错误, so that 可以修复问题而不是面对无响应按钮。
18. As a 交互终端用户, I want 在真实终端中输入、执行命令和使用 Ctrl+C, so that Hub 可以替代独立终端进行日常操作。
19. As a 交互终端用户, I want 切换会话和调整窗口后仍保留终端状态, so that 不会丢失当前工作。
20. As a 交互终端用户, I want 普通临时终端默认不记录输入或持久化输出, so that 不产生无意义日志。
21. As a 交互终端用户, I want 结束后仍能回看本次终端输出, so that 可以检查执行结果。
22. As a 交互终端用户, I want 可以移除已结束的临时终端, so that 列表不会无限积累。
23. As a 交互终端用户, I want 真正退出 Hub 后不恢复未保存的临时终端, so that 下次不会重复打开临时工作。
24. As a 交互终端用户, I want 可以保存终端启动方式, so that 常用目录和 shell 能够复用。
25. As a 交互终端用户, I want 保存配置不会保存或重放之前执行的命令, so that 再次使用不会意外重复任务。
26. As a 应用用户, I want 通过独立的“添加应用”入口保存启动配置, so that 配置长期应用与快速新开终端区别明确。
27. As a 应用用户, I want 配置应用名称、工作目录和启动命令, so that Hub 能正确启动并标识应用。
28. As a 应用用户, I want 可以选择 Hub 内显示或独立窗口, so that 不同应用使用合适的展示方式。
29. As a 应用用户, I want 可以补充用途、关闭影响、端口、网页地址和日志策略, so that 能判断应用状态和停止后果。
30. As a 配置维护者, I want 保存新配置保留已有配置内容, so that 手动维护的设置不会丢失。
31. As a 配置维护者, I want 保存冲突、格式错误和写入失败有明确反馈, so that 不会误以为配置已经保存。
32. As a 应用用户, I want 保存后的应用立即出现在列表且下次仍可使用, so that 不需要重启才能发现新增配置。
33. As a 应用用户, I want 点击已运行应用选中已有会话, so that 不会启动第二份。
34. As a 应用用户, I want 启动中的重复点击不会再创建进程, so that 双击或窗口恢复不会造成重复运行。
35. As a 独立窗口应用用户, I want 点击入口唤起已有应用窗口, so that 可以直接返回应用。
36. As a 应用用户, I want 在 Hub 外先运行的应用也能在可靠识别时复用, so that 不需要关闭后再从 Hub 启动。
37. As a 应用用户, I want 无法确定已有实例时能选择关联或明确新开, so that Hub 不会替我盲目创建另一份。
38. As a 自带控制台的应用用户, I want Hub 推荐独立窗口模式, so that 不重复展示应用已经提供的控制台。
39. As a 应用用户, I want 可以修改展示模式推荐, so that Hub 不会仅凭名称替我决定运行方式。
40. As a 独立窗口应用用户, I want 默认停止全部和退出 Hub 不关闭该应用, so that 正在运行的第三方任务保持独立。
41. As a 应用用户, I want 可以明确启用 Hub 的生命周期管理, so that 需要统一启停的应用能够由 Hub 管理。
42. As a 交互终端用户, I want 关闭终端时明确知道其所属子进程也会结束, so that 不会误判关闭影响。
43. As a 多会话用户, I want 结束某个终端只结束其所属进程树, so that 其它会话和无关程序继续运行。
44. As a 托盘用户, I want 关闭主窗口只隐藏到托盘, so that 受管会话继续运行并能恢复交互。
45. As a Windows 用户, I want 系统和其它软件自行启动的终端保持原行为, so that Hub 不干扰它们的工作流程。
46. As a Windows 用户, I want 界面只有一层深色标题栏且常规窗口操作正常, so that Hub 形成完整一致的窗口。
47. As a Windows 用户, I want 各入口使用选定的 Hub 图标, so that 能快速辨认应用身份。
48. As a 用户, I want 窗口唤起失败时看到真实结果而不是再启动一份, so that 可以信任复用行为。

## Implementation Decisions

1. **保持现有职责边界。** Session Core 拥有受管会话及生命周期事实；配置层负责读取、校验和安全保存；PTY 层负责终端输入输出；Windows 进程层负责进程归属；应用层协调启动请求与窗口恢复；前端只维护视图状态。窗口、快捷方式与托盘使用同一应用操作边界。
2. **单实例先于会话启动。** 在当前 Windows 用户的日常运行环境内，先确认或建立唯一 Hub，再执行请求。第二次调用向已有 Hub 转交请求并结束，不初始化另一份会话监管器。不依赖窗口标题匹配认定实例，不在规格阶段锁定未经验证的系统 API 或插件。
3. **显式区分三类启动请求。** 普通打开只恢复 Hub；新建 PowerShell 恢复 Hub 并新增临时终端；打开已配置应用执行启动或唤起。请求包含操作、目标配置身份或目录以及必要的关联身份，返回实际结果或具体错误。冷启动期间有界接收并等待服务可用，不能静默丢弃。相同交付的重试避免重复执行，不同的用户新建动作分别执行。
4. **动态创建是正式后端能力。** 在现有会话接口上增加临时终端创建、保存启动配置、添加应用和移除已结束临时项的完整操作。创建返回稳定会话身份与真实状态，选中意图和后端列表更新配合；不能由前端制造一个缺少后台会话的行。空工作区也提供新建入口。
5. **目录与 shell 解析。** 默认优先已安装的 PowerShell 7，未安装则使用 Windows PowerShell。应用内默认用户主目录；外部入口提供目录时使用该目录。按参数语义处理空格及 Unicode，不能把目录拼接为待执行命令。目录不存在、没有权限或 shell 无法启动时明确失败，不静默切到系统目录。
6. **临时终端和已保存配置分开。** 临时项不自动写入长期配置；结束后保留内存输出和列表，允许移除，真正退出后不恢复。保存只记录 shell、目录等启动方式，不采集命令历史，不重放命令，也不为已运行终端额外创建一个重复进程。
7. **两种入口清晰分开。** 快速主入口为“新建 PowerShell”；次要入口为“添加应用”。前者立即创建，后者提供表单。已有混合文案取消。表单必填名称、工作目录、启动命令；展示模式可选，其他用途、关闭影响、端口、网页地址与日志策略可选，继续使用已有校验与日志默认规则。
8. **展示方式与生命周期归属是不同设置。** Hub 内显示使用合适的受管服务或真实交互终端；独立窗口保留应用自己的界面与控制台。独立窗口默认不由 Hub 管理启停，用户可以单独启用管理。扩展配置和 DTO 明确表达这两个维度，不能用是否捕获日志或是否有端口代替它们；旧配置继续维持原有行为。
9. **模式推荐不能冒充可靠识别。** 对能够确认自带控制台的已知启动方式推荐独立窗口，用户可更改。ComfyUI 直接启动与秋叶启动器不能只因同名而采用同一模式。未知应用保留可选择的模式，不声称已完成自动识别；本规格不要求建立通用智能分类器。
10. **启动应用是幂等的激活操作。** 已运行配置选中已有会话并唤起相关窗口；启动中请求等待或聚焦同一启动过程；停止中不并行拉起下一份。未运行应用再创建一次运行。保留显式重启的停止屏障，不将点击打开解释为重启。
11. **可靠实例关联。** Hub 启动的应用以已持有的运行身份及窗口关联为依据。Hub 外应用需要能够验证的可执行目标、启动上下文和进程／窗口身份，防止 PID 重用或同名误认；仅有名称或占用端口不能证明同一实例。身份不确定时显示关联或明确新开的选择；关联已有实例不自动取得终止权限。应用没有可唤起窗口或 Windows 拒绝前台切换时报告实际结果，不通过重复启动补救。
12. **独立窗口默认存活于 Hub 退出之外。** 默认模式必须从创建时就不受 Hub 退出清理影响，不可沿用“关闭监管句柄会终止树”的受管资源并声称只是展示不同。停止全部和退出计划排除默认独立应用；显式受管的独立窗口应用继续遵守已有优雅停止、强制结束和真正退出确认规则。
13. **终端关闭结束所属进程树。** 终端 shell 开始执行前建立可靠进程树归属；创建、归属或恢复失败清理本次资源。结束会话后确认树消失，再呈现结束状态，不只终止 shell 的 PID。不按名称或端口全局终止进程。Ctrl+C 保持终端中断语义，不等同关闭；终端会话关闭与服务优雅停止仍有不同语义。
14. **动态列表一致性。** 扩展现有注册表快照与事件协调，新增配置与临时项在主窗口和托盘正确出现，移除后不会被迟到快照复活。创建、保存、终止和刷新有确定顺序及失败语义，初始化、隐藏窗口、快速切换和请求乱序不丢项、不生成幽灵项；避免靠持续高频轮询掩盖问题。
15. **配置保存具有文件安全边界。** 新建或追加配置复用已有校验，保留无关条目、顺序、注释与用户维护的内容；对不能安全修改的格式或未知内容明确拒绝，不做有损重写。写前检查原文件是否已变化并原子替换；只在持久保存确认后反馈成功。运行中新增配置能够显示且重启 Hub 后仍可加载，既有进程不因保存被重启。
16. **日志行为保持真实。** 普通临时 shell 默认只有有界内存滚动缓冲，不自动生成持久输出或 stdin 日志。既有手动记录和服务日志策略继续生效；独立窗口应用没有捕获输出时不能伪造 Hub 终端或记录状态，关联自有日志也不意味着重复捕获控制台。
17. **快捷方式使用明确入口。** 将用户选择的日常 PowerShell 快捷方式目标改为 Hub 的新建终端请求，保留入口目录意图。该修改限定于显式选用的入口，不能修改系统 shell 可执行文件或全局接管其他进程。提供可理解的入口安装／替换方式，避免用户日常依赖开发终端。
18. **统一窗口身份。** 使用用户选定的内部 Hub 图标作为可复现的资产来源，并更新应用、任务栏、托盘与快捷方式图标集。取消重复系统标题展示，将拖动、缩放、最小化、最大化、还原、关闭及 Windows 常规窗口交互接到保留的深色标题栏；关闭仍隐藏到托盘。保留 V2 的其它布局和颜色语义。
19. **实现时同步相关规范。** 本规格是新增功能的行为基线：快速创建不再留作后续候选功能，既有图标决策应记录用户本次变更。此前未实现／未验收事实不能被文档改写成已通过；完成实现和验收后再更新完成状态。

## Testing Decisions

- **用户已明确确认测试边界。** 以真实 Windows 应用和快捷方式操作作为主要验收；复用现有 Session Core 集成边界检查真实进程、配置与日志，以前端注册表协调边界补充动态列表同步。优先复用这两个边界；Windows 窗口／启动请求只在应用边界补足必要验证，不为每个模块新增一套 mock。
- 好的测试检查实际会话、窗口、进程树、配置文件、日志及可观察失败，不断言内部函数调用次数、锁结构或组件私有状态。结果必须区分通过、失败和未运行。
- 沿用已有 Windows 多会话集成矩阵：从隔离的真实配置加载到 Session Core 公共操作，使用真实 ConPTY shell 和可协调的测试子进程；针对动态创建、保存、受管归属和树终止增加行为验证。不重复已有低层测试已经充分覆盖的 PTY 功能。
- 进程验证使用子进程握手证明归属和结束，覆盖立即创建后代、父进程先退出、关闭、归属失败及无关同名哨兵存活。终端结束只能在受管树消失后通过；不以延时或一次压力测试通过作为唯一证据。
- 配置验证覆盖首次无文件、追加已有配置、包含空格和 Unicode 的目录、非法输入、格式损坏的 YAML、权限失败、并发外部修改和未知内容。断言失败未破坏原文，成功保存可在实际加载链路中复用，并与运行时一致。
- 复用现有前端注册表协议测试，覆盖创建期间初始读取、配置与运行态不同返回顺序、迟到事件、保存、移除、取消监听及恢复连接。断言最终用户列表与后台事实一致，不用模拟 IPC 证明真实终端可用。
- 单实例在真实应用入口验证：两个近乎同时启动请求、第二次普通打开、两个独立新建动作、同一请求重试，以及隐藏／最小化恢复。观察 Hub 数量、运行身份和终端数量，确认普通打开不误建 shell、主动多开不被去重。
- 独立窗口使用可控 GUI 测试程序验证默认退出 Hub 后窗口与子进程仍存活、显式受管时正确启停；另验证用户所举秋叶启动器场景。验证已持有实例、Hub 外实例、不可确定身份及前台切换失败，不把同名匹配视为通过。
- 原生自动化若只能操作 WebView 内容，它可以证明真实 IPC 与终端交互，但不能证明任务栏窗口数量、托盘操作、系统装饰或快捷方式图标。必须补充相应 Windows 窗口操作、截图和进程证据；无法执行时逐项列为未运行。
- 含真实子进程、ConPTY、进程树控制或 Windows 进程检查的测试，通过正常逐命令审批机制在已登录的 Windows 用户环境中运行；源文件检查、类型、Lint、格式和普通构建留在配置的沙箱。记录实际身份、构建版本、隔离目录和清理结果，不能用沙箱失败代表 Windows 原生结果。
- 复用项目现有前端检查、构建和 Rust 检查，不因本规格引入全仓测试框架。只在实现后执行对应回归及下表验收；本次发布规格不声称任何新增行为已通过。

## Out of Scope

- 全局拦截或接管任意 PowerShell、CMD、Windows Terminal、IDE、AI Agent 和第三方后台终端；修改 shell 可执行文件或强行替换系统默认控制台宿主。
- 将已经打开的外部控制台画面强行搬进 Hub、恢复先前终端执行现场或重放命令历史。
- 通用应用自动识别引擎、仅靠名称／端口自动关联、未经明确设置终止外部应用及不可靠的 PID 全局清理。
- 为默认独立窗口应用强行捕获控制台或重复保存自有日志；提供任意受管进程在退出时安全分离的通用能力。
- 新增 CMD／其他 shell 快速入口、工作区启动组、全局快捷键、依赖编排、HTTP／Busy 适配器、资源监控或跨平台支持。
- 全面重做 V2 界面、替换技术栈、引入新的日志默认隐私策略、代码签名、自动更新和新发布渠道。
- 本次规格发布不实现功能、不发布安装包、不认领或关闭现有工单、不将旧验收记录改写为新增功能通过。
