# Roadmap

Roadmap 的目标不是承诺固定日期，而是明确开发顺序、阶段边界和每一阶段的完成标准。

## Phase 0：设计冻结与技术验证

目标：在写大量业务代码前，验证最关键的技术风险。

需要完成：

- 确定 Windows 优先技术栈；
- 验证 ConPTY/PTY 交互；
- 验证多会话并存；
- 验证进程树追踪与停止；
- 验证窗口隐藏到托盘后会话继续运行；
- 验证终端输出高吞吐时 UI 不阻塞；
- 验证日志可以与终端显示解耦。

完成标准：

- 能启动一个 PowerShell；
- 能输入命令；
- 能 resize；
- 能 Ctrl+C；
- 能同时保留两个以上会话；
- 主窗口隐藏后进程继续运行；
- 一个会话结束不会影响其它会话。

## Phase 1：最小可用 Hub

目标：把“任务栏里散落很多终端”真正收进一个窗口。

功能：

- 本地配置文件；
- 左侧受管会话列表；
- Service / Interactive Terminal 两种类型；
- 启动 / 停止 / 重启；
- PID 与基础状态；
- 嵌入式交互终端；
- 会话切换；
- 用途与关闭影响；
- URL / 端口信息；
- 打开网页；
- 打开工作目录；
- 点 X 收入托盘；
- 托盘恢复；
- 明确的真正退出。

### Phase 1 验收

至少能配置并同时运行：

1. SillyTavern；
2. ComfyUI；
3. 一个 PowerShell 交互会话。

要求：

- 三者统一出现在 Hub 中；
- PowerShell 可输入；
- 服务输出可查看；
- 切换不会丢失状态；
- 关闭主窗口不会停止服务；
- 单独停止某会话不会误杀其它会话。

## Phase 2：有序日志与运行历史

目标：让日志“需要时存在，而且之后找得到”。

功能：

- Terminal Buffer；
- `off / always / manual / on_error / auto`；
- `none / captured / external`；
- run_id；
- 每次运行元数据；
- 按 session / 年月分类；
- 日志路径 UI；
- 打开日志 / 打开所在目录；
- 日志轮转；
- 保留策略；
- 异常运行历史。

完成标准：

- 普通交互终端默认不产生磁盘日志；
- 开启捕获的服务能按 run 找到历史；
- external log 不被无意义复制；
- on_error 可以保留错误前有限缓冲；
- 日志目录脱离 Hub UI 仍可人工理解。

## Phase 3：服务状态与依赖

目标：从“进程管理”提升到“本地服务管理”。

功能：

- 端口检查；
- HTTP 健康检查；
- Ready / Busy / Degraded / Unhealthy；
- 服务依赖；
- 启动顺序；
- 停止顺序；
- 依赖未启动时提示；
- 可选自动重启；
- 优雅停止超时策略。

可能的例子：

```text
KoboldCpp ──> SillyTavern
API       ──> Frontend
```

## Phase 4：工作区与效率功能

目标：降低日常操作成本。

候选功能：

- Workspace / 启动组；
- 一键启动一组本地应用；
- 一键停止一组；
- 快速新建受管 PowerShell / CMD / pwsh；
- 从目录上下文创建会话；
- 收藏；
- 搜索；
- 标签过滤；
- 最近使用；
- 全局快捷键；
- 托盘快速操作。

## Phase 5：资源与诊断

目标：提供足够的状态信息，但避免变成任务管理器。

候选功能：

- CPU；
- 内存；
- GPU 使用情况（按可行性）；
- 网络端口；
- 子进程树；
- 异常退出统计；
- 最近错误；
- 日志搜索；
- 状态快照。

原则：默认低频、按需获取，不能因为“监控”本身产生明显资源占用。

## Phase 6：扩展能力

可能方向：

- 应用适配器；
- 插件化健康检查；
- 特定应用状态解析；
- 配置导入导出；
- 便携模式；
- 跨平台；
- Remote session；
- CLI 控制接口；
- 本地 API。

这些内容不应提前进入 MVP，除非它们解决了当前实现的基础架构问题。

## 明确延后

以下内容初期不做：

- 全局劫持所有系统终端；
- AI Agent 后台子进程自动纳管；
- 完整任务管理器；
- Docker/Kubernetes 替代品；
- 默认记录所有输入输出；
- 复杂账户系统；
- 云同步；
- 为了“看起来高级”而加入高频资源监控。

## 优先级判断原则

新增功能在进入开发前至少回答：

1. 它是否解决“本地服务 / 终端管理”的核心痛点？
2. 它是否会让 Hub 明显变重？
3. 它是否破坏“受管与非受管边界”？
4. 它是否引入隐私或日志风险？
5. 它能否先做成可选项？
6. 它是否应该属于插件，而不是核心？
