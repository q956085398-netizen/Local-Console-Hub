# 下一版计划：端口监视

更新：2026-10-04。监听列表、占用进程、受管会话关联、启动前冲突提示、刷新和查找已接入现有 Hub。HTTP 健康探测、资源监视、全局进程管理和自动结束占用者仍未做。

初版已针对运行中服务的配置端口，约每 5 秒检查 `127.0.0.1` TCP 可达性。这一读数保持原意：它不是 HTTP 健康，也不证明监听者属于当前会话。端口监视是在这之上增加的本机监听列表和占用进程。

| 准备更新 | 预期效果 | 状态 |
| --- | --- | --- |
| 本机监听端口列表 | 展示协议、监听地址和端口；TCP 与 UDP 分开，UDP 说明套接字不等于正在收发 | 已接入现有 Hub |
| 占用进程 | PID、进程名、可取得的程序路径；权限不足或字段读不到时显示信息不可用 | 已接入现有 Hub |
| 关联受管会话 | 核实进程身份及所属树后关联；其它标为外部，不仅凭端口推定归属 | 已接入现有 Hub |
| 启动前冲突提示 | 端口已占用时展示占用者与详情，提示用户处理，不自动结束进程 | 已接入现有 Hub |
| 变化与刷新 | 监听新增/消失、最近检查时间、刷新中；端口页打开且窗口可见时低频自动刷新，另有手动刷新 | 已接入现有 Hub |
| 查找与定位 | 按端口、进程和会话查找，打开对应受管会话 | 已接入现有 Hub |
| HTTP 健康探测 | 不把 TCP 可达写成 HTTP 健康 | 未做 |
| 资源监视 | 不监视 CPU、内存等资源 | 未做 |
| 全局进程管理 | 不做 Hub 以外的进程管理 | 未做 |
| 自动结束占用者 | 不自动结束占用端口的进程 | 未做 |

## 完成标准

1. 真实 Windows 程序打开/关闭端口后，在刷新周期内反映变化；验证 TCP、UDP、IPv4、IPv6。
2. 端口占用、进程退出及 PID 复用时归属准确；无法取得信息时显示信息不可用。
3. 外部程序占用配置端口时有具体冲突提示，不误停外部或其它会话。
4. 展示最后检查时间、刷新中与失败状态；窗口隐藏时降低或暂停可视列表轮询，不用旧数据冒充实时。
5. 基础查看不要求管理员权限；额外权限字段有清楚提示。
6. 完成真实 Windows 端口/进程取证和回归，模拟数据不替代原生验证。
